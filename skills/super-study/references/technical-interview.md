# Technical interview track

Use this as the full first-version track for frontend, backend, data, AI, agents, and cybersecurity interview preparation.

## Inputs

Accept a topic, job description, GitHub repository, local project or folder, file, pasted material, or URL. When several job descriptions exist, keep separate target notes and derive a shared competency matrix. Prioritize common requirements before role-specific ones.

## Coverage model

For each topic, select relevant angles from:

- definition and mental model;
- mechanism, lifecycle, data flow, or control flow;
- implementation and API behavior;
- debugging signals and common production failures;
- performance, scalability, reliability, and observability;
- alternatives, constraints, and engineering tradeoffs;
- security and abuse cases;
- version-sensitive behavior;
- communication under interview follow-ups.

Weight a node by real-project probability, interview frequency, and transfer value. Ignore trivia and unusually narrow details unless the target source makes them material.

## Practical verification

Prefer prediction, tracing, debugging, code review, design change, incident diagnosis, and minimal implementation over fact-only quizzes. Use isolated runnable experiments where feasible. Keep source projects read-only by default.

Test three layers:

1. **Explain**: define the concept and mechanism accurately.
2. **Do**: implement, trace, debug, design, or review it.
3. **Defend**: handle changing constraints, counterexamples, failure, and tradeoffs.

## Job-description mapping

Extract explicit requirements, implied capabilities, seniority signals, and preferred experience. Map them to Topics and Concepts, then compare them with existing mastery evidence. Store why each learning node matters to the job description; do not create duplicate Concepts per employer.

## Project mapping

Start from the repository tree, README, dependency manifests, entry points, tests, configuration, and architecture boundaries. Read implementation files only as the current branch requires. Distinguish project-specific behavior from general practice and official behavior.

## Interview simulation

Remove hints. Ask one primary question, then follow the learner's answer with mechanism, failure, alternative, scale, security, and counterfactual probes. Stop a branch only when its material dimensions are verified or a precise learning gap has been recorded.
