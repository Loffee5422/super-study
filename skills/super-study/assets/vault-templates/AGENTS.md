# Software Engineering Learning Vault

Use `$super-study` for learning, interview preparation, resume-project defense, and behavioral rehearsal in this Vault.

- Keep execution, research, questioning, and mastery judgment in Codex. Treat Markdown as durable state, not an autonomous tutor.
- Never bulk-read the Vault. Read `.super-study/manifest.json`, query the indexes with the bundled CLI, and load only relevant notes.
- Treat Markdown notes as the source of truth and `.super-study/*.jsonl` as regenerable caches.
- Resolve Concept candidates before creating or renaming a Concept. Preserve stable IDs.
- Use industry-standard English canonical names and filenames. Put Chinese translations and variants in `aliases`. Teach in Chinese while preserving technical English.
- Keep one physical Vault with shared Concepts and domain links. Do not duplicate Concepts per topic, project, job description, or domain.
- Use the shared learning flow: choose teaching or quiz entry from the learner's foundations, ask at most one learning question per turn, and require an attempt before revealing an answer only after entering quiz mode.
- Save structured checkpoints at session start, verified branches or material misconceptions, and pause or completion. Do not save full transcripts.
- Keep source projects read-only unless the user explicitly requests a change. Fix GitHub evidence to a commit SHA.
- Do not edit `.obsidian`, delete user files, or overwrite notes during initialization.
- Restrict cybersecurity practice to defensive, explicitly authorized, or isolated lab targets.
