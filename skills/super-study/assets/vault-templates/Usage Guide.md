# Super Study 使用说明

`super-study` 是一个由 Codex 执行的渐进式深度学习工具，主要用于软件工程面试准备，也支持简历项目深挖和行为面试训练。

> [!important]
> 你只需要在 Codex 中描述学习目标。研究、提问、练习、掌握判定、索引和学习档案都由 Codex 处理，不需要手动运行 Vault 脚本。

## 快速开始

在 Codex 中显式调用：

```text
$super-study 带我彻底掌握 JavaScript Event Loop，用技术面试标准训练我。
```

也可以直接描述目标；当请求匹配时，Codex 可以自动使用该 skill。

每轮只处理一个知识分支、提出一个主要问题。学习不会被默认时间限制；达到当前学习契约的掌握标准后才会完成。

## 可以提供什么输入

### Topic

```text
$super-study 带我掌握数据库索引，覆盖常见项目难点和面试追问。
```

适合学习前端、后端、数据、AI、Agent、网络安全等高频软件工程知识。

### Job Description

粘贴 JD 内容或提供链接：

```text
$super-study 基于这份 JD 分析能力差距，并从最高优先级 Topic 开始训练我：<JD>
```

多份 JD 会保留独立目标，同时生成共享能力矩阵，优先学习重复出现且迁移价值高的要求。

### GitHub 项目

```text
$super-study 基于 https://github.com/owner/repo 深挖这个项目，并训练我应对项目面试。
```

Codex 会记录仓库、跟踪分支和本次实际使用的 commit SHA。私有仓库需要当前 GitHub 连接具备访问权限。

### 本地项目、文件或网页

```text
$super-study 根据这个项目文件夹教我它的认证架构：C:\path\to\project
```

```text
$super-study 根据这个官方文档带我掌握该 API：<URL>
```

用户材料是本次要理解的对象；Codex 仍会使用官方文档、标准或一手资料核验其中的过时内容和错误。

## 三种学习 Track

### 技术面试

默认 Track，覆盖：

- 概念和机制；
- 实现、代码追踪和调试；
- 常见生产故障；
- 性能、扩展性和可靠性；
- 替代方案与工程权衡；
- 安全影响；
- 连续面试追问和新场景迁移。

### 简历项目深挖

```text
$super-study 深挖我简历中的这个项目，检查我的描述是否能被 GitHub 代码支持。
```

重点验证架构、个人贡献、关键决策、困难问题、失败经历、指标、权衡以及反事实追问。

### 行为面试

```text
$super-study 根据这份 JD 训练我的冲突处理和失败复盘经历。
```

重点验证经历真实性、个人行动、结果、反思和追问一致性，不编造角色、指标或结果。

## 一次学习如何进行

```text
来源与已有档案
    ↓
确定学习契约和边界
    ↓
诊断已有理解
    ↓
渐进提示与短讲解
    ↓
新场景重新验证
    ↓
闭卷追问
    ↓
无提示模拟面试
    ↓
Teach-back 与掌握判定
```

如果发现阻塞当前理解的前置知识，Codex 会临时进入前置分支；达到最低必要水平后立即回到主线。其他延伸知识不会阻塞当前 Topic 完成。

## 答错时会发生什么

提示分为五级：

- Level 0：无提示；
- Level 1：指出缺失的维度；
- Level 2：给出方向性提示；
- Level 3：给出关键线索；
- Level 4：进行短讲解。

使用 Level 2–4 后答对不算正式掌握。Codex 会换一个新场景，在无提示条件下重新验证。

## 什么叫“掌握”

“我懂了”、看懂答案或重复刚刚的解释都不算掌握。根据当前 Topic，通常需要证明：

- 能无提示回忆并用自己的话解释；
- 能说明机制和因果关系；
- 能实现、使用、调试或审查；
- 能识别边界、失败模式和常见误区；
- 能比较替代方案和工程权衡；
- 能分析安全与运行影响；
- 能解决新的场景；
- 能承受连续面试追问并完成 Teach-back。

掌握度按维度记录，不使用平均分掩盖关键短板。

## 暂停、继续和复习

暂停当前学习：

```text
暂停并保存当前学习检查点。
```

继续上次进度：

```text
$super-study 继续上次未完成的学习路径。
```

开始复习：

```text
$super-study 开始今日到期复习。
```

暂停不会把 Topic 标记为已掌握。档案会保存未解决分支、重要误区、已验证证据和下次的第一道测试。

## Obsidian 中看什么

- [[00 Home/Start Here|Start Here]]：总入口和知识库概览；
- [[00 Home/Current Learning|Current Learning]]：正在学习、待开始或需要复习的 Topic；
- [[00 Home/Review Queue|Review Queue]]：已经到期的复习项目；
- Frontend、Backend、Data、AI、Agents、Security MOC：各领域导航；
- `10 Topics`：学习契约、知识地图和分维度掌握状态；
- `20 Concepts`：可跨 Topic、项目和 JD 复用的概念；
- `30 Sessions`：结构化学习证据，不保存完整聊天记录；
- `40 Sources`：来源、版本、commit 和冲突；
- `60 Targets`：不同 JD 的要求与能力差距；
- `.super-study`：Codex 使用的可重建索引，无需手动编辑。

## 来源和引用

来源优先级默认是：

1. 用户提供的项目或材料；
2. 已连接的 MCP 或 Connector；
3. 官方文档、标准、规范、论文和仓库源码；
4. 高质量二手资料。

聊天中只在关键事实、版本差异和争议点处展示引用；更完整的来源关系保存在 Vault 中。

## 项目与安全边界

- 用户项目默认只读；
- 实践代码默认在隔离临时目录运行；
- 写回项目、提交或推送必须得到明确授权；
- Vault 不保存 GitHub token、密钥或 `.env`；
- 网络安全实践仅限防御、明确授权的项目、本地靶场或合法 CTF；
- 不对真实第三方目标进行扫描、利用、凭据获取或持久化。

## 常见问题

### Skill 没有出现在 Codex 中

重启 Codex，再输入 `$super-study` 检查技能列表。

### Vault 中出现同名或相似 Concept

不要手工新建第二份。让 Codex 运行 Concept 解析，决定复用、增加 alias、创建特定变体或创建新概念。

### 导航页没有更新

告诉 Codex：

```text
使用 super-study 重建 Vault 索引并验证链接。
```

### 想改变当前范围

直接说明新的 JD、项目、目标岗位或希望加入的真实项目难点。Codex 会更新学习契约，但不会因为冷门细节无限扩大范围。
